# 对照实验：如何快速锁定「地图资源」接口

## 原则

一次 HAR 只验证一个假设。动作越单一，候选越少。

## 实验矩阵

| 实验 | 操作 | 期望 |
|------|------|------|
| E1 首进 | 清空 Network → 进沙盒地图 → 导出 | 静态地图 + 初始状态都会出现 |
| E2 刷新 | 刷新后再进图 → 导出 | **静态地图接口仍在**；部分一次性资源可能消失 |
| E3 移动 | 只移动一格 → 导出 | **状态接口**变化大；**静态地图**几乎不变 |
| E4 换层 | 换楼层/区域（若有）→ 导出 | 可能换一批 map id / 新地图包 |
| E5 重开迷雾 | 开视野相关操作 → 导出 | 视野/fog 字段变化 |

## 判定规则

```
若 URL 在 E1∩E2 都出现，且 body 结构几乎相同
  → 高概率「静态资源 / 地图定义」

若 URL 在 E1、E3 都出现，但 body 差异大（当前位置、已访问）
  → 高概率「进度 / 状态」

若只在进图瞬间出现一次、刷新后没有、且是超大二进制/图片
  → 多半是美术资源，不是逻辑地图

若 JSON 内有 width/height + cells[] 或 二维 int 数组
  → 优先当地图解析
```

## 把结果交给 AI 时最少提供

1. 候选 URL（analyze_har 前 5 名）  
2. 对应 `out/*.json` 文件（可打码 cookie）  
3. 你在游戏里看到的地图特征：格子大小、是否六边形、有无楼层、障碍怎么表现  

## Cookie / 鉴权

- HAR 里会带 Cookie，**不要**把完整 HAR 发到公网  
- 本地分析没问题  
- 若需要我帮你写「只读复现请求」脚本，用环境变量注入 Cookie，不要写进仓库  

## 路径规划输入（确认 schema 后）

最少需要：

- 可走格子集合 / 邻接表  
- 起点、终点（或目标类型：宝箱、出口、事件）  
- 可选代价：体力、战斗、陷阱  

输出：格子序列或方向序列。
