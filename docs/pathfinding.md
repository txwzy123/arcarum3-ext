# 路径规划方案（对齐 arcarumDungeon / 贤者肉鸽助手）

参考仓库：`Desktop/arcarumDungeon-main` 的 `src/path/`。

## 两套算法

### 1. 面板常用：目标导向加权寻路（`weightedRoute.js`）

**用途**：从当前位置走到指定目标（可加途经点）。

| 项 | 内容 |
|----|------|
| 算法 | **Dijkstra**（堆实现） |
| 图 | 无向图：`node_id` + `adjacent_node_ids` |
| 边权 | 按「**进入**邻接点」计费，不是边本身 |
| 途经 | 分段 `start → via1 → … → goal` 再拼接；尽量不重复中间点，失败则放宽 |

#### 三种预设

| 预设 | 行为 |
|------|------|
| **最短 (short)** | 每步计惩罚；空地 `1500`、危险 `5000`、其它 `1000`；**不**额外鼓励收益 |
| **收益 (reward)** | **词典序**（见下） |
| **安全 (safe)** | 同收益，但 Boss/强敌 **禁止** |

Boss 是终局节点：任何预设都不会把 Boss 当作途经点穿过，只有显式选择 Boss 为最终目标时才允许进入。

#### 「收益」预设：词典序（解决 1空+1奖 vs 1空+2奖）

比较两条路径时按顺序：

1. **惩罚分 `primary` 越小越好**  
   - 空地 +1500  
   - Boss/强敌 +5000  
   - 其它内容格 +1000  
   - **战/事/箱：+0（不进惩罚）**
2. 惩罚相同 → **`rewards`（战/事/箱个数）越多越好**  
   - 例：`1 空地 + 1 奖励` vs `1 空地 + 2 奖励`  
   - primary 同为 1500，rewards 2>1 → **两条奖励更优**
3. 仍相同 → **步数越少越好**

这样不会出现「多一个奖励格反而更差」（旧版 +1 代价会有这个问题）。

实现常量：

```
EMPTY_ENTER_COST = 1500
AVOID_ENTER_COST = 5000
COST_STEP        = 1000   // 中性格
// 收益格：primary += 0，rewards += 1
```

#### 操作（本扩展地图窗口）

- **左键**：查看节点详情  
- **右键**：第一次设**目标**（粉色框），再右键其他点加**途经**（紫色框）  
- 顶栏预设切换后自动重算  
- 路径蓝色高亮，右侧显示步数 / 高价值格 / 危险格

### 2. 阶段 1 扫图：预算内收益最大化（`stage1.js`）

**用途**：在步数上限内，尽量多途经高价值格（开荒/刷资源阶段）。

| 项 | 内容 |
|----|------|
| 算法 | **DFS + 乐观上界剪枝** |
| 得分 | 路径上（**不含起点**）type ∈ {2,5,6} 的个数 |
| 硬避开 | type ∈ {1,3} 不可进入 |
| 路径 | 简单路径（节点不重复） |
| 传送门 type9 | 可 0 步传到其他门 |
| 浮空城传送 si∈{5,6,7} | 可 0 步落到某传送门；结果分「不用浮空城最优」与「用浮空城最优」 |

本扩展 **当前只接入第 1 套**（目标加权寻路）；阶段 1 DFS 可后续再加。

---

## 与「网格 BFS」的区别

游戏地图是 **显式邻接图**，不是格子四连通。  
正确做法是走 `adjacent_node_ids`，而不是按 `position_x/y` 做网格 BFS。

## 3. 收益扫路（无目标，点数上限 ≤ N）

模块：`arcarum3-ext/shared/path/exploreScore.js`。

| 项 | 约定 |
|----|------|
| 起点 | `current_node_id`（不需要终点） |
| 长度 | **2..N** 点（含起点），滑窗默认上限 10，可调 5–16；**可短于 N** |
| 简单路径 | 不重复节点 |
| 目标 | **累计分最低**（同分取更短） |
| Boss | 不参与无目标扫路；显式目标寻路允许到达，但只能作为最终目的点 |

### 计分（进入格，不含起点；`EXPLORE_WEIGHTS`）

| 类型 | 第一天 | 第二天 |
|------|--------|--------|
| 普通战斗 (2) | −10 | −10 |
| 事件 (5) | −10 | −10 |
| 宝箱 (6) / 商店 (8) | −10 | −10 |
| 回复 (7) | +10 | +10 |
| 空地 (0) | +10 | +10 |
| 君临者 (4) / 传送 (9) / 特殊 (10) | +10（同空地） | +10 |
| 强敌 (3) | **+10（可撤退，同空地）** | **−10（奖励）** |
| Boss (1) | 不参与 | 不参与 |
| 超强敌 (11) | +10（可撤退，同空地） | +10 |

累计分越低越好。日程用 `inferDay(state)`；回复开关在地图窗「收益扫路」面板。

### 算法

DFS 枚举长度 **≤ N** 的简单路径：每走到合法深度都登记候选，再决定是否继续扩展。  
剪枝用乐观下界（剩余步 × 最负单步分），**不会**「单步变差就停」——因此仍会穿过空地去够更远的 −10。  
N 较大时最坏很慢，有展开上限；UI 用绿线显示。

与「恰好 N」的差别：后面若净收益为负，可以提前结束，不必为空地硬凑满 N。

### 走一步后路线为什么会变？（不是算错）

≤ **N** 的滚动规划仍有「地平线效应」：

1. 计划在上限 N 内最优。  
2. 走到 B 后，B 的 `node_type` 常变为 **0（空地）**，收益已吃掉。  
3. 若从 B 再开一个 ≤N 窗口，总行程预算变长，最优解可能改道。

扩展的对策（`map.js` + `exploreScore.js`）：

| 行为 | 说明 |
|------|------|
| **移动时只裁剪** | `trimExploreRouteToCurrent`：仍在绿线上则截掉已走前缀，**不重算** |
| **手动「生成路径」带粘性** | `findLowestScorePathSticky`：旧剩余为候选；新方案好不过 `REPLAN_STICKINESS`（默认 8）才换路 |
| **目标寻路同理** | 仍在蓝线上则 `trimTargetRouteToCurrent`；偏离才 Dijkstra 全量重算 |

验证脚本：`arcarum3-ext/_test_le_n.mjs`、`_test_sticky.mjs`。

## 4. 毒圈（金色安全区）活动偏好（软约束）

当 `miasma_info.*.is_miasmic === true` 时：

| 规则 | 说明 |
|------|------|
| 适用 | **目标寻路** + **收益扫路** |
| 目标 | **在金色安全区内活动即可**，**不**以圆心为终点 |
| 安全区几何 | 圆心 `center_position_x/y` + 半径（`pattern_id`→圈图半边长；pattern 1 = **670**） |
| 安全区判定 | 距圆心 ≤ 半径 → 圈内；`is_shrinking=true` → 圈外/瘴气 |
| 数据补全 | 服务端若尚未标 `is_shrinking`，`ensureSafeZoneShrinking` 按位置关系回填 |
| 方式 | **软性**：进入 `is_shrinking` 加代价；圈内游走无额外项；**不删边** |
| 系数 | 扫路 `MIASMA_OUTSIDE_ENTER_SCORE=14`；目标寻路 `MIASMA_OUTSIDE_ENTER_PRIMARY=2200` |
| 地图 | 金色半透明大圈 + 中心十字；紫虚线 = 瘴气边 |

离线补全脚本：`tools/_apply_safe_zone.py`（已写回 `out/miasma_dungeon_snapshot.json`）。
